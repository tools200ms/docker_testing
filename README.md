# Simple Docker Testing Framework (docker-tester.sh)

This is the simple Docker image testing framework written in Bash.

Features: 
- Technically no dependencies (but Linux must NOT be Musl based).
- Provides assertion and exception handling.
- Provides `network supevisor` that allows on network response tests.
- Detailed information if tests fail.
- Allows for running all tests, or just specific ones.

## How to use it
To set up a framework, follow the following steps: 
1. Go to directory where `Dockerfile` is (recommended).
2. Download `docker-tester.sh` into this directory.
2. Create `tests.sh` with the following content: 
```bash
set -- "$@"
source $(dirname $0)/docker-tester.sh

# Create 'network supervisor'
create_neti "true" "ip6"

# ADD TESTS HERE

# Stop 'network supervisor'
clean_neti

exit 0
```
3. Add desired tests.

**NOTICE:** Framework provides `supervisor` that is launched as separate container attached to the same Docker bridge network. It can be used to test image's network response. To use `supervisor` created it at the beginning (`create_neti`) and clean it after all tests (`clean_neti`).

### Defining tests
Test block starts with `run` followed by `test` or `test_neti`. The block must be terminated with `stop`.

`run` creates container (with `docker run`) for testing purposes. `test` invokes provided command within that container. `test_neti` invokes command within `network supervisor` that should be used to test network response of tested container. For clarity see below: 

```bash
# Create 'run' (docker run)
run "def. var." "volume list"
  # do tests ...
  test "command" "assertion"
  # do tests from 'network supervisor'
  # {host} is tested container's host name
  # (assigned by docker)
  test_neti "command {host}" "assertion"
  
# stop run (docker stop)
stop
```
**NOTICE:** that *assertion* is not obligatory. 

Test is passed when: 
- Command returns *0* as return code.
- If assertion is defined, it will be tested against stdout generated by command. If it is passed, the test is passed.

Assertion is Bash conditional statement (`[[...]]`), see example below: 
```
test_neti "curl --retry 3 --retry-connrefused --max-time 5 -o /dev/null -s -w '%{http_code}' http://{test}:8080" "== 200"
```

### Checking for exceptions

`run_expect_error` is used for testing if container fails as expected (`docker run`). See below: 

```bash
# handle exception at container's launch: 
run_expect_error "command" "assertion" "expected error code"

```

**NOTICE:** 'stop' command is not necessary (container is desired for failure anyway).

### Preparing `network supevisor`

`network supevisor` is a lightweight image designated for testing network responce of tested container. Supervisor contains the following network tools: 
- curl
- ping

Extra tools if necessary can be added as follows (with Alpine `apk add`): 
```bash
# create_neti with extra commands: 
create_neti "apk add dropbear-dbclient"
```
